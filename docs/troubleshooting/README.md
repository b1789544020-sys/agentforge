# 故障案例库

这里保存可复用的真实失败，而不只保存最后的绿色结果。每个案例应回答：**当时在完成什么目标、怎样复现、为什么失败、怎样定位、如何修复、最终怎样证明修复有效**。

| --- | --- | --- | --- |
| [P0 原依赖 pin 与 Python 3.12 验证](p0-pinned-python/README.md) | 关闭 P0/16.1 的干净环境验收 | Python 3.14 源码构建、FastAPI 204 导入断言、pytest-asyncio 顺序失败、共享内存 SQLite 生命周期 | 已修复，验证计数见案例 |

## 收录约定

1. 保存失败命令、关键原始输出和退出码；成功截图不能替代失败证据。
2. 日志可以删去重复堆栈，但必须标注“摘录”，保留错误类型、关键帧和最终计数。
3. 不收录 API Key、Token、数据库密码或客户数据；本机绝对路径可替换为 `<repo>`、`<home>`、`<venv>`。
4. 区分**事实、推断和未验证假设**。单个用例通过不等于顺序套件通过，目标环境通过不等于所有 Python 版本通过。
5. 记录试过但无效的方案，避免下一位维护者重复走弯路。
6. CLI 故障优先保存终端文本；确有浏览器或桌面 UI 失败时再附截图，并在正文说明截图对应的步骤。不得用示意图冒充现场截图。
7. 最终结论必须链接到修复后的验证结果；若仍有失败，状态保持“处理中”，不能包装成已解决。

## 新案例最小模板

```markdown
# 标题
- 日期 / 环境 / 状态
- 目标与业务背景
- 前置条件
- 最小复现步骤与实际退出码
- 预期结果 / 实际结果
- 根因与排除过的假设
- 修复内容（含无效尝试）
- 修复后验证与剩余边界
- 原始证据索引
```
