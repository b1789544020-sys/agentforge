# AgentForge 后续开发规划

> 本文集中记录后续迭代方向、技术验证边界和历史失败基线。仓库首页与展示视频用于介绍已实现功能；具体完成状态以实际代码和验收证据为准。

## 1. 真实模型与研究助理质量

- 保留本地研究助理 Definition A 的真实探针结果：5 次请求均完成，但完整回答契约为 **0/5 通过**。该基线只代表这组直接客户端探针，详见[专项设计](LOCAL_RESEARCH_ASSISTANT.md)。
- 在相同模型、资料、检索条件和输入下比较后续 Prompt / Definition，补充来源完整性、跨资料回答、证据不足和提示注入检查。
- 将真实 Provider 接入 AgentLoop、Studio、质量门禁和交付链路，保存端到端运行证据。
- 增加多轮重复执行与波动统计，校准检索语义相关性、引用支持度和回答完整性。

## 2. Studio 与开发者体验

- 在现有单 Agent 三栏 Studio 上增加创建向导和更完整的工作空间导航。
- 评估自然语言配置草案、受控 Prompt 修改建议和人工审核工作流。
- 规划多 Agent 定义、资源关系与调试体验；复杂自主多 Agent 暂不进入当前稳定主路径。
- 完善首次体验测量，记录首次运行、首个测试和首次交付的步骤、耗时与阻塞点。

## 3. 知识与工具质量

- 验证真实中文 embedding、扫描 PDF OCR、复杂表格和大型文档异步处理。
- 扩充检索 Trace、证据分数门槛与引用支持度评测。
- 持续完善受控只读工具、危险操作审批和沙箱目标环境验证。

## 4. 生产与私有化验收

- 在目标 Linux / Docker 环境验证 PostgreSQL、Redis、Qdrant、Celery 多 worker 和持久卷重启。
- 验证公网反向代理、受信代理链、iframe 矩阵、备份恢复、故障恢复和性能。
- 在目标离线及信创环境分别验证安装物料、CPU / OS / 加速硬件组合。
- 保留 Python 3.14 原 pin 构建差异、GPU Provider 故障和前端依赖审计项，按实际环境逐项处理。

## 5. 展示与文档维护

- 根目录 README、`docs/demo.md` 和根目录视频采用能力导向的产品展示口径。
- 技术验收、失败基线和未决事项集中保留在 `docs/planning/`，不删除历史证据。
- 展示内容只描述已经实现的能力；新功能完成并验证后，再同步到首页和展示视频。
