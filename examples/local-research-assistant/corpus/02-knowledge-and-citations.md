# 知识检索、版本与引用

## 文档与定位信息

AgentForge 的知识库可以导入 UTF-8 Markdown 等文档，并按标题、段落和句子边界切片。检索结果包含文件名、章节、切片 ID、正文和相似度分数。回答中的 `[1]` 等编号应当对应本次实际提供给模型的证据，不能只因为输出里出现了一个数字就认定引用正确。

需要区分三个对象：检索候选、真正注入模型上下文的证据，以及回答最终引用的来源。候选被返回不代表它一定支持答案；来源文件存在也不代表模型中的事实由该来源支持。验收时应同时保存检索结果、注入顺序、原始回答和人工核查结论。

## 默认检索与真实 embedding 的边界

默认的进程内向量实现使用确定性 hashing embedder，将词、中文字符和中文二元组映射到固定维度。它不需要训练权重，适合可重复的离线工程测试，但不能被描述成 bge-m3 等真实语义模型。代码另提供可选的 SentenceTransformer 适配器；是否可用取决于独立依赖和本地模型文件。

本机 Ollama 中出现 `bge-m3-cpu` 或 `embeddinggemma` 条目，并不表示 AgentForge 已经通过 Ollama 调用它们。接入真实 embedding 需要单独实现或配置、核对向量维度、重建索引并评价检索召回。不能混用不同模型生成的向量，也不能只凭模型名称宣称中文检索质量已经提高。

## 知识绑定和资料变化

canonical Agent Definition 通过包内 `ref` 表达知识资源，导入或 Studio 保存时必须用 `resource_map` 显式映射到调用者可访问的目标知识库。知识绑定保存进 AgentVersion 后，后续修改当前 Agent 的绑定不应暗中替换旧版本已经固定的绑定关系。

绑定关系被固定不等于文档正文、切片和向量被永久冻结。知识内容仍属于共享资源，更新文档可能改变后续检索结果。因此，不可变 AgentVersion 不是比特级研究复现保证；需要严格复现时，还应保存资料清单、内容哈希、切片与检索结果。

## 证据不足与引用验收

对资料未覆盖的问题，合格回答应直接说“现有资料不足以可靠回答该问题”，指出缺少哪类资料，并避免给弱相关候选添加引用。仅仅附上一个看似相关的来源，或者根据模型记忆补充答案，都不合格。

当前候选包把拒答要求写入 Prompt，用于真实模型可行性观察；它不是经过校准的证据门槛。完整验收还需要按资料和问题校准检索分数或覆盖规则，并保留误拒答与应拒未拒两类失败。引用编号、来源定位和事实支持关系都要检查，文本相似度不能替代这些判断。

## 研究记录的最小字段

一次可复核的研究运行至少要保存用户输入、AgentVersion、Provider、实际模型 ID、采样参数、开始和结束时间、原始输出及错误。知识部分还要保存资料清单及内容哈希、检索问题、候选切片、分数、排序、实际注入顺序和最终引用。无法确认的字段应标为未知，不能用推测值补齐。

如果多次运行同一问题，每次结果都要单独保留，不能只保存平均分或最好的一次。模型、Prompt、资料和 embedding 任一变化都应进入比较条件。人工核查需要记录结论和理由；自动格式检查通过但人工发现来源不支持结论时，应以失败样本保留并进入后续复测。
